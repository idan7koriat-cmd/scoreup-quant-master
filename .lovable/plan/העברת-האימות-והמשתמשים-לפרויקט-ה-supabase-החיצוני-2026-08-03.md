# העברת האימות והמשתמשים לפרויקט ה-Supabase החיצוני

## מה קרה עכשיו (מאומת)

- קובץ `.env` מנוהל אוטומטית וחזר להצביע ל-backend המובנה של Lovable Cloud, ולכן ההרשמה של `idan7koriat@gmail.com` נשמרה שם. יש שם בדיוק פרופיל אחד שנוצר ב-03/08 22:42 UTC.
- הפרויקט החיצוני שלך משמש רק לשליפת שאלות (`src/lib/questions.functions.ts` דרך הסודות `EXT_SUPABASE_URL` / `EXT_SUPABASE_ANON_KEY`), ולכן טבלת המשתמשים שם ריקה.

## המטרה

כל האימות, הפרופילים והתקדמות התרגול יעברו לפרויקט החיצוני שלך, יחד עם השאלות.

## מה נבנה

1. **לקוח אימות לפרויקט החיצוני**
   - מודול חדש `src/lib/extAuthClient.ts` שיוצר לקוח Supabase לדפדפן מול הפרויקט החיצוני, עם שמירת סשן ב-localStorage.
   - הכתובת והמפתח הפומבי יגיעו מפונקציית שרת קטנה (`src/lib/extConfig.functions.ts`) שמחזירה את ערכי הסודות הקיימים — כך לא צריך להוסיף סודות חדשים.

2. **החלפת השימוש בלקוח הישן**
   - `src/routes/auth.tsx`, `src/hooks/useSession.ts`, `src/routes/dashboard.tsx`, `src/routes/index.tsx` וכל מקום שמבצע התחברות/הרשמה/יציאה יעברו ללקוח החדש.
   - שמירת הפרופיל (תאריך בחינה, תואר מבוקש) וקריאת `is_premium` / `last_quick_practice` יפנו לפרויקט החיצוני.
   - `solved_questions` ייכתב גם הוא לפרויקט החיצוני, כך שהשאלות והתקדמות יושבים באותו מקום.

3. **סכימה בפרויקט החיצוני**
   - אכין לך סקריפט SQL מוכן להרצה בפרויקט שלך: יצירת `profiles` ו-`solved_questions`, הרשאות, RLS, וטריגר שיוצר פרופיל אוטומטית בהרשמה.
   - את הסקריפט צריך להריץ בפרויקט החיצוני (אין לי גישת כתיבה אליו), ואז נמשיך.

4. **התחברות עם Google**
   - הכפתור הנוכחי עובד דרך המתווך המנוהל של Lovable, שקיים רק ל-backend המובנה. מול הפרויקט החיצוני נעבור ל-`signInWithOAuth('google')` של Supabase, ואתה תפעיל את ספק Google בהגדרות הפרויקט שלך (Client ID + Secret + Redirect URL).
   - עד שתפעיל את הספק, התחברות עם Google תיכשל; אימייל+סיסמה יעבוד מיד.

## נקודות שחשוב שתדע

- המשתמש הקיים לא עובר אוטומטית — תצטרך להירשם מחדש בפרויקט החיצוני (או להוסיף את המשתמש שם ידנית).
- אישור מייל: אם תרצה שההרשמה תתחבר מיידית כמו היום, צריך להפעיל Auto Confirm בהגדרות האימות של הפרויקט החיצוני.
- ה-backend המובנה יישאר קיים אבל לא ישמש יותר לאימות.

## פרטים טכניים

- הלקוח החיצוני ייווצר עם `createClient(url, anonKey, { auth: { persistSession: true, storageKey: 'scoreup-ext-auth' } })`.
- קריאות שרת שדורשות זהות משתמש (למשל סינון `solved_questions`) יקבלו את ה-access token מהלקוח החיצוני ויאמתו אותו מול הפרויקט החיצוני בתוך ה-handler.
- `src/integrations/supabase/client.ts` ו-`.env` נשארים ללא שינוי (מנוהלים אוטומטית).
